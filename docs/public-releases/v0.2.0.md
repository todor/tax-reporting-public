## Highlights

- Added SPB-8 support for foreign accounts and securities, including IBKR-derived cash/securities rows, manual CSV input, aggregate reporting, and omission of rows whose rendered end-of-year value is zero.
- Standardized main reports and diagnostics across analyzers, with Bulgarian user-facing status reasons near the top of the main report and technical evidence moved into diagnostics output.
- Reworked expected analyzer warnings into structured diagnostics with stable codes, centralized Bulgarian and English rendering, deduplication, severity ordering, and clearer aggregate status summaries.
- Expanded IBKR coverage for CFDs, Payment in Lieu of Dividend rows, futures, equity/index options, forex review inheritance, withholding-tax reversals, and incomplete Activity Statement detection.
- Added generic per-input opening state handling for stateful crypto analyzers, including sidecar `.state.json` auto-detection and aggregate-mode mappings.
- Improved release reliability with committed release notes validation for GitHub Releases and expanded synthetic example validation.

## Tax-impacting changes

- SPB-8 output is now generated as part of individual and aggregate reports. IBKR cash balances are derived from the Cash Report by original currency, while IBKR securities are reconstructed from Open Positions, Trades, Transfers, and instrument metadata. Transfers affect SPB-8 beginning quantity reconstruction only; they do not change Appendix 5 tax P/L.
- Manual SPB-8 CSV input now uses a generic amount/ISIN-aware schema and supports overrides with analyzer-derived fallbacks when fields are left empty. Missing required SPB-8 values now move reports to `NEEDS_REVIEW`, and incomplete SPB-8 filing sections are suppressed until the user supplies enough data.
- IBKR CFDs are reported in Appendix 5, Table 2, code 508. CFD trade values now use realized P/L rather than notional turnover: positive P/L is reported on the sale/income side and negative P/L on the acquisition/cost side. CFD financing can be netted into Appendix 5 by default or routed/skipped with the documented CLI option.
- Payment in Lieu handling was added for IBKR dividend rows. Positive PIL is routed to Appendix 6, code 606, while negative PIL is netted into Appendix 5 by default unless disabled.
- IBKR futures are supported using Mark-to-Market Performance Summary as the taxable P/L source. Futures trade counts are based on actual trade executions, while monetary totals use MTM amounts to avoid double counting.
- IBKR equity and index options are supported for closed or expired lots through Appendix 5, Table 2, code 508. Exercise/assignment rows without ClosedLot data are not treated as standalone taxable events and now receive structured diagnostics.
- IBKR withholding tax handling now nets positive withholding-tax reversals, clamps Appendix 8/9 creditable foreign tax at zero, and prefers detailed Appendix 9 interest withholding rows over Mark-to-Market fallback data.

## IBKR input and review behavior

- IBKR Activity Statements must now have EUR as the base currency. Missing or non-EUR base currency fails early with a structured, actionable main-report error.
- Incomplete IBKR statements with realized disposal activity but no ClosedLot rows are detected as input errors with guidance to export full Trades / Closed Lots / Lot Details.
- Single IBKR runs now default to the same tax-exempt classification mode as aggregate mode, and the effective classification setting is shown in both individual and aggregate reports.
- Forex review statuses now support `TAXABLE-FROM-HERE` and `NON-TAXABLE-FROM-HERE`, applying inherited status only to subsequent blank Forex rows while preserving per-row overrides.
- Corporate Actions are detected and propagated through the result contract. When present, IBKR SPB-8 type 04 start quantities are left empty for review.
- Manual-review diagnostics now include concrete row examples with listing exchange data, mapped classification, execution exchange, and actionable Bulgarian guidance.

## Reports and diagnostics

- Main reports now have one standardized status banner and keep user-actionable errors, warnings, and review items near the top. Raw parser details, tracebacks, file evidence, and technical audit lines belong in diagnostics reports.
- Aggregate reports now include top-level reason blocks for `ERROR` and `NEEDS_REVIEW`, per-analyzer status labels, deduplicated analyzer notes, and structured diagnostics instead of repeated free-form warning sections.
- Expected analyzer issues across crypto, fund, P2P, Binance futures, IBKR, and SPB-8 paths now use stable diagnostic codes and centralized renderers. `UNCLASSIFIED_*` diagnostics remain only as defensive fallback.
- Report paths are rendered as normal filesystem paths rather than `file://` URLs, and stdout is kept operational: status, report paths, diagnostics path, and short summary counts.
- Analyzer interpretation notes that affect tax treatment or auditability are now emitted through a generic `MainReportNote` contract so aggregate reports include them consistently.

## Input handling and workflow

- Aggregate mode can auto-detect a single `*spb8*.csv` input file, respects `--include-pattern`, and keeps an explicit `--spb8-input-file` as the highest-priority selection.
- `--no-spb8` now suppresses SPB-8 rows, notes, templates, input validation, and status impact.
- Generic `--opening-state-json` replaces analyzer-specific aggregate opening-state flags. It supports simple mappings, per-input mappings, alias-qualified mappings, and sibling `.state.json` sidecar files.
- Selected SPB-8 input files and opening-state resolution are visible in diagnostics, while ignored candidates are reported without being mistaken for analyzer inputs.

## Documentation, examples, and release validation

- README and analyzer documentation were updated for SPB-8 workflows, IBKR automation, manual CSV behavior, EUR base-currency requirements, CFD/PIL/futures/options treatment, forex review inheritance, structured diagnostics, and standardized report conventions.
- Sanitized example data now includes manual SPB-8 input and a synthetic IBKR Activity Statement covering CFDs, futures, options, PIL, and Appendix 5 non-trade adjustment audit details.
- Binary release validation now relies on normal aggregate usage with input-folder detection of the SPB-8 file, and GitHub Releases now require committed Markdown release notes before release creation or update.
- Release validation recorded in the commits includes full pytest and ruff runs, targeted analyzer tests, normalized example-output comparisons, workflow-style report diffs, workflow YAML parsing, and packaged/binary release checks.
