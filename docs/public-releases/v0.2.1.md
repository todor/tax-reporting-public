## Highlights

- Aggregated reports now carry forward the important information emitted by individual analyzers, so the combined main TXT and diagnostics TXT are no longer missing analyzer-specific assumptions, decisions, warnings, or audit details.
- Aggregate diagnostics were reorganized into a cleaner, English-only audit structure with per-input sections instead of duplicated pasted copies of individual diagnostics.
- The Bulgarian aggregate main report is more focused on declaration use: action items are grouped by severity, generic settings are separated from report-specific notes, and verbose audit values stay in diagnostics.
- Analyzer-generated row-level audit CSV artifacts are now surfaced in reports and diagnostics where relevant, making it easier to find supporting files produced during a run.
- IBKR annotated CSV output now explains more row-level tax decisions, including effective market classification, tax-year scope, CFD financing treatment, and futures MTM handling.

## Reports and diagnostics

This release improves the reporting contract between individual analyzers and aggregate outputs. Analyzer details now have explicit visibility for main report, diagnostics, or debug-only use, which helps prevent important information from disappearing when several inputs are combined into one aggregate report.

Aggregate diagnostics are now self-contained and organized around the full run: run summary, input inventory, per-analyzer status, per-input summaries, input interpretation, tax calculation summaries, tax treatment decisions, analyzer audit facts, validation checks, generated artifacts, and debug artifacts. The aggregate diagnostics no longer embed complete individual diagnostics files verbatim, and the old top-level IBKR-specific policy blob has been replaced by clearer per-input tax treatment decisions.

Input accounting is also clearer. Analyzer inputs, auxiliary/manual inputs, and ignored inputs are counted separately, so manual files such as SPB-8 inputs do not inflate analyzer success counts. Files intentionally excluded by `--include-pattern` remain visible in diagnostics but are suppressed from the Bulgarian main ignored-files section, avoiding noisy warnings for files the user deliberately excluded.

## Main TXT report usability

The aggregate Bulgarian TXT output now separates three concerns more deliberately:

- user actions, grouped by errors, manual-review items, and warnings;
- compact tax settings and assumptions, such as tax year, calculation/display currency, analyzers used, P2P treatment, crypto/fund opening-state assumptions, and IBKR classification modes;
- declaration values and detailed methodology notes.

Verbose extracted source-report values from P2P analyzers are no longer printed in the aggregate main report. They remain available in diagnostics for audit and troubleshooting. Report-specific notes that explain non-actionable tax behavior can still appear compactly when useful, while duplicate main-report messages are reduced.

IBKR market classification notes are consolidated across aggregate inputs, so the main report avoids repeated or conflicting rows such as showing both “none” and later concrete market values for the same classification group.

## Analyzer artifacts

Analyzers can now expose generated audit artifacts through a shared mechanism. When row-level audit CSV files are produced, the main Bulgarian report can list them under “Помощни файлове за проверка”, and diagnostics list them under “Generated artifacts” for the relevant input. These paths are kept separate from debug artifacts and are normalized consistently for golden-output validation.

## IBKR row-level audit CSV

The IBKR modified CSV now includes additional compact audit columns where they materially explain row-level decisions:

- `Tax Exemption Market Classification` records the effective market/regulatory classification used for the row under the configured IBKR tax-exempt mode.
- `Tax Year Scope` marks relevant rows as `IN_TAX_YEAR` or `OUTSIDE_TAX_YEAR`.
- CFD financing rows in the `Fees` section are annotated with EUR amount, appendix target, tax treatment reason, and tax-year scope.
- Futures Mark-to-Market Performance Summary rows are annotated as the taxable Appendix 5 source.
- Futures trade rows are marked as not directly summed when the MTM summary drives the taxable result.

The CSV writer also avoids leaving blank source columns between original section data and added audit columns.

## Documentation and validation

Documentation and expected example outputs were updated for the new report structure, diagnostics layout, ignored-input handling, methodology placement, generated artifact paths, and IBKR audit annotations.

Release validation recorded in the commit history includes full `uv run pytest` and `uv run ruff check` runs, along with targeted regression coverage for aggregate propagation, diagnostics layout, include-pattern filtering, P2P report-note cleanup, IBKR market classification consolidation, generated artifacts, and IBKR row-level CSV annotations.
